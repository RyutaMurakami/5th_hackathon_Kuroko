## 0. このシナリオで確かめること

## 2. 本編

どちらの画面も、3人ぶんのチャット（幹事・赤坂 くらお・赤くら 花子）が最初から並ぶ。**幹事の列の先頭に、いつも「次にすること」が出る**。迷ったら、それに従う。幹事の入力は、すべてチャットの流れの中のカードで行う。

### 手順1. 依頼して、計画を確定する（幹事）

- **操作**
  1. 入力欄の上の候補「今日の19時から、第一開発チーム10人の歓送迎会を…」を押し、「送る」を押す
  2. 返事のあと、チャットの中に出る「計画を確定する」のカードで、題名・日時（今日の19時）・エリア・人数 10・予算を確かめて、「この内容で進める」を押す（10秒ほどかかる。規程の文書から値を読み取って検証している）
  3. （規程をたずねる）候補「部長と新人の負担はどう違いますか？規程を確認してください」を送る
- **期待する結果**
  - 送った発言がすぐに出て、「KUROKOが考えています…」と経過の秒数が出る
  - KUROKO が、**イベントの ID を聞き返さずに**、依頼をふまえた返事をする
  - 確定すると、「次にすること」が 2/9（出欠と委任に答える）になり、くらお・花子の列に「出欠と委任」のカードが出る
  - 規程の質問には、**「第4条」などの条番号を添えて**答える。個別の金額は計算しない
- **確かめること**: ☐ 考え中の表示 ☐ ID を聞かれない ☐ 2/9 になる ☐ 条番号つきの答え

### 手順2. 出欠と委任に答える（くらお・花子）

- **操作**: A: 2人の列のカードの「参加して、委任に同意する」を押す／B: 2人それぞれの Slack の DM で同じボタンを押す
- **期待する結果**
  - カードに、上限額（花子 12,000円・くらお 6,000円）・支払先（幹事だけ）・期限が書いてある
  - 押すと「回答済み」になる。2人とも押すと、3/9（店）に進む
  - A でも、Slack の2人に同じ DM が届いている。先に押したほうが有効で、もう一方も回答済みになる
  - B では、画面の列にボタンが出ない（届いたカードを映すだけ）
- **確かめること**: ☐ 上限額が区分どおり ☐ 2人目のあとに 3/9 ☐（B）列にボタンが無い

### 手順3. 店を選び、予約を確定する（幹事）

- **操作**
  1. 2人が出欠に答えると、KUROKO が自分で店を探し始める（30秒ほど。「お店を探しています…」と出る。うまく進まないときだけ「もう一度探す」を押す）
  2. 候補の「この店にする」を押す
  3. 「サンプルの予約画面を送る」を押す（チャットに画像が送られ、KUROKO が読み取る）
  4. 入力欄に入った値（店名・日時・人数 10・コース単価 4,950円）を確かめて、「この内容で確定する」を押す（参加者の DM に、開催の案内が届く）
- **期待する結果**
  - 候補が最大3件出て、それぞれに選んだ理由（帰りやすさ）が付く
  - **「神田 寅鈴」が候補にあれば、「記憶」の印と「前回（2026/06）このチームで利用…」が付く**（事前に入れた記憶。候補の先頭に来る）
  - 予約画面の値が、入力欄に入る。確定すると 4/9（開催後）に進む
- **確かめること**: ☐ 候補と理由 ☐ 記憶の理由 ☐ 予約の読み取り ☐ 4/9 になる

### 手順4. 開催が終わった、を押す（幹事）

- **操作**: チャットの中の「開催が終わった」を押す
- **期待する結果**: 5/9（領収書）に進む

### 手順5. 領収書の金額を確定する（幹事）

- **操作**: 「サンプルの領収書を送る」を押す（チャットに画像が送られ、KUROKO が読み取る）。読み取った金額を確かめて、「この金額で確定する」を押す
- **期待する結果**
  - 読み取った合計が **49,500円**
  - 確定すると、チャットの中に「按分の内訳」が出る。0章の期待値と**1円も違わない**。「値は、規程の文書から AI が読み取り、コードが検証したもの…負担係数は第4条…」と根拠が出る
  - 6/9（承認）に進み、花子の列（B では花子の Slack）に承認依頼が届く
- **確かめること**: ☐ 49,500円 ☐ 按分が期待値どおり ☐ 根拠の条 ☐ 6/9 になる

### 手順6. 按分を承認する（花子）

- **操作**: A: 花子の列の「この按分を承認する」を押す／B: 花子の Slack で押す
- **期待する結果**
  - 承認依頼は花子にだけ届く（くらおには届かない）
  - 7/9（銀行）に進み、**くらお（2,100円）と花子（4,800円）に、振込の承認の依頼**が届く
  - 1〜2分のうちに、代行の5人が支払い済みになる
- **確かめること**: ☐ 花子だけに届く ☐ 7/9 になる ☐ 2人に銀行の依頼が届く

### 手順7. 銀行で、2人の振込を承認する（くらお・花子）

- **A（体験）の操作**: 2人の列の「銀行で承認する（体験用）」を押す → 銀行の承認ページを模した画面で「承認する」を押す
  - **期待する結果**: 振込先（幹事の口座）と金額が出る。「振込の承認が完了しました」と出る。sunabar には送られない。Slack の DM の同じボタンでも承認できる
- **B（実演）の操作**: `acct02`（くらお）と `acct03`（花子）のログインIDで sunabar のサービスサイトに入り、「お知らせ」から振込の承認ページを開いて、取引パスワードで承認する。**依頼から10分以内に、2人ぶん**
  - **期待する結果**: 承認する振込が、幹事の口座あてで、くらお 2,100円・花子 4,800円。10分を過ぎると、自動で依頼が作り直され、もう一度 DM が届く（最大2回）
- **どちらも**: 承認から1〜2分で、その人のカードが「入金を確認しました」になる
- **確かめること**: ☐ 金額と宛先 ☐ 2人とも支払い済みになる

### 手順8. 入金の確認と、振り返りの開始（**自動**）

- **操作**: 何もしない。1〜2分待つ
- **期待する結果**
  - 幹事口座の入金明細で7人ぶん（17,400円）が確認され、**すぐに振り返りが始まる**（8/9）
  - くらお・花子に、満足度（1〜5）を聞くカードが届く（A: 列と Slack／B: Slack）
  - チャットの中に「振り返りと、KUROKO が覚えること」のカードが出る（回答 0 / 2名）
  - （B）sunabar の `acct01`（幹事）の明細に、2,100円と 4,800円の入金が1件ずつ増えている
- **確かめること**: ☐ 自動で進む ☐ 満足度のカードが届く

### 手順9. 振り返りに答え、記憶に保存する（くらお・花子 → 幹事）

- **操作**
  1. くらお・花子が、満足度のボタン（例: 5 と 4）を押す（待たずに進めるときは、幹事が「回答を締め切る」）
  2. 幹事が、チャットの中の振り返りのカードで、「次回も、この店を使いたいですか」に答え、「次回に覚えさせる」を押す
- **期待する結果**
  - 2人が答えると、9/9（幹事の確認）になり、満足度の平均（例: 4.5）と、覚えさせる文（実績・評価の2つ）が出る。**個人ごとの回答は出ない**
  - 実績の文: 「第一開発チームの歓送迎会（年/月）で『（選んだ店）』を10名で利用。1人あたり4,950円（コース4,950円）で予算内。」
  - 保存すると「記憶に保存済み」になり、イベントが終了する
  - **「新しく依頼する」から、もう一度手順3まで進めると、今回の店に「記憶」の理由が付く**（同じアカウントで作ったイベントだけ）
- **確かめること**: ☐ 2人が答えると集計される ☐ 文が定型どおり ☐ 保存できる ☐ 次の企画で使われる

### 終わったら

- ☐ 下の記録欄を埋める
- ☐ しばらく通しをしないなら、定期実行を止める（AI に頼む。`scheduler_paused = true` → `terraform apply`）
